# Tech stack

*This document covers every tool and external service, with the rationale, trade-offs, and reinstatement triggers behind each choice. System-level context — how these pieces fit together — is in [`ARCHITECTURE.md`](ARCHITECTURE.md); this document implements ADR-0001, Part 3 ("Updated architecture") at the tool-selection level, and the free-tier ceilings and execution-mode changes in ADR-0002. Decisions are cited inline as "ADR-0001, D-XX" or "ADR-0002, D-XX."*

## In the MVP

- **Claude Pro + Claude Code** — the current, free-tier-first execution path for the LLM pipeline (ADR-0002, D-20). The founder runs the same extraction-fallback, topic-synthesis, and thesis-generation prompts described in `docs/AI_SYSTEM.md` personally, through Claude Code (in Cursor or a terminal, authenticated via the existing Pro subscription — no separate API key) or directly in claude.ai. Usage draws from the Pro plan's shared quota rather than metered billing, at zero incremental cost. One operational note worth keeping visible: if an `ANTHROPIC_API_KEY` environment variable is ever set on a machine running these sessions, Claude Code silently switches to metered API billing instead of the subscription — keep it unset anywhere this project's work happens. The fully automated version of this same pipeline (Haiku 4.5 / Sonnet 5 / Opus 4.8 called from scheduled jobs, with the Batch API's 50% discount available once volume justifies it) is deferred — see below.
- **Finnhub** — market data, free tier. 60 calls/minute, real-time US quotes, fundamentals, and SEC filings — enough for daily snapshot ingestion at MVP scale (`docs/ARCHITECTURE.md`, Data ingestion). Worth naming explicitly: IEX Cloud, an earlier default choice for projects like this one, was fully shut down in August 2024. It still shows up often enough in older tutorials and templates that it's worth a standing warning — do not build against it. Massive.com (formerly Polygon.io, rebranded October 2025) is the paid upgrade path once revenue justifies it (see Deferred, below); it no longer offers a free tier, which is exactly why it isn't the MVP default. Confirmed via direct API test during the M0 concierge test (2026-07-28): the free tier does not cover quotes for non-US exchanges — `AAPL` returns real data, while XETRA/LSE/Euronext Paris/Borsa Italiana symbols (confirmed correct via Finnhub's own symbol-search endpoint) all return an access-denied error on the same key. This is a real scope constraint now, not a suspicion: new topic write-ups default to US-listed companies or US-listed ADRs unless a deliberate decision is made to pay for expanded coverage (see Deferred, below, for a documented free-tier alternative worth testing first if this becomes a recurring need rather than a one-off).
- **Supabase** — Postgres + authentication. Bundling auth in the same product removes a separate service (Clerk, Auth0) that would otherwise need wiring up and paying for independently — even though auth itself sits unused until M5 (ADR-0001, D-07), having it provisioned and ready removes a whole integration task from that milestone when it arrives. Per ADR-0001 D-04, Supabase's role in this stack grew beyond the original plan: with no deployed backend service, the Supabase client plus row-level security is what the frontend reads through directly, and a Postgres function exposed as an RPC is the escalation path for anything beyond a straightforward filtered read. Neon remains a reasonable alternative specifically if per-branch database copies (one branch per feature or PR) become valuable to the workflow — pick one and move on rather than running both; nothing in the MVP currently needs that capability. Confirmed free-tier-viable at this project's scale (ADR-0002, D-21): the free tier includes 500MB database, 5GB egress/month, 500K edge function invocations/month, and up to 2 active projects — with one operational quirk worth naming, a free project pauses after 7 days with no database activity. In practice the scheduled jobs' own hourly writes prevent this from ever triggering; see `docs/ARCHITECTURE.md`, Free-tier operating notes, for what happens if the jobs themselves go quiet first. Upgrade trigger: approaching the 500MB database ceiling, which isn't expected for years at this content volume.
- **Vercel** — frontend hosting. Next.js's first-party deployment target: zero-config CI from a git push, an edge network well suited to the public, indexable, shareable pages that are the actual product surface (`docs/VISION.md`, Why publication, before dashboard), and a free tier that comfortably covers MVP traffic. Netlify is a reasonable substitute for a Next.js app but doesn't offer anything Vercel doesn't already cover here — no reason to introduce a second vendor relationship for parity. One term worth flagging explicitly (ADR-0002, D-21): Vercel's Hobby (free) tier is restricted by its own terms of service to non-commercial, personal use, and Vercel enforces this. That's not a new constraint introduced by this decision — it rides on the same trigger `docs/MVP_SCOPE.md` already sets for monetization generally (counsel review, first). As long as that gate hasn't been crossed, Hobby is the right tier; the moment it is, upgrading to Vercel Pro (~$20/month) is the same decision, not a separate one.
- **GitHub Actions** — scheduled job execution and CI. Replaces the original plan's Railway Cron (ADR-0001, D-04): the same workflow that runs lint, type-check, and tests on every push also triggers the six scheduled jobs (`docs/ARCHITECTURE.md`) on cron schedules, with no second platform, no second billing relationship, and no separate place to check when a job silently stops running. The trade-off is a hard ceiling on job runtime and a less full-featured scheduler than a dedicated worker platform — acceptable at MVP volume, and explicitly the condition that brings a real worker platform back if it's ever hit (see Deferred, below). Confirmed genuinely free and unmetered at any volume this project will reach (ADR-0002, D-21) — standard GitHub-hosted runner minutes are free without a cap specifically because this repository is public; that would not hold on a private repo. The one behavior worth planning around isn't cost, it's dormancy: GitHub automatically disables a public repository's scheduled workflows after 60 days with no commits (not no job runs) — see `docs/ARCHITECTURE.md`, Free-tier operating notes, for the low-effort mitigation.
- **Resend** — weekly email digest. Pulled into the MVP stack rather than deferred to a later milestone, since the publication is the actual M3 deliverable, not an add-on to it (ADR-0001, D-18). Chosen over Postmark mainly on developer experience and Next.js-ecosystem familiarity — both are legitimate choices for transactional and digest email at this scale, and this isn't a decision worth spending much more time on than it takes to read this sentence. Subscriber emails for the digest live in Resend's own audience feature rather than a custom Postgres table (`docs/DATA_MODEL.md`, Consolidation notes) — no reason to duplicate list management the email provider already does well. The free tier covers 3,000 emails/month and one verified sending domain — comfortably enough for the MVP, with one concrete ceiling worth watching (ADR-0002, D-21): a 100/day cap, which collides directly with `docs/ROADMAP.md` M3's own "first 100+ subscribers" target if the whole list is emailed in a single day. Worth checking subscriber count against this before hitting it, not after; the fix is either spreading a large send across more than one day or upgrading to Resend Pro ($20/month) — by then, a genuinely good problem to have. A verified domain is a hard requirement for sending beyond the account owner's own address, regardless of provider — see Domain registration, below.
- **Domain registration** — the one line item in this stack that isn't free anywhere, and isn't trying to be (ADR-0002, D-22). A verified custom domain is a functional requirement for Resend to send to anyone beyond the account owner, and was always going to be needed by M3 for a credible, shareable public page regardless of the cost constraint — a `*.vercel.app` URL can't be verified for DNS-based email authentication, because Vercel, not the founder, controls its DNS. Typically $10–15/year; if the founder already owns a domain for any other purpose, a subdomain of it costs nothing further.
- **Sentry** — error tracking. Unchanged from the original plan; a standard choice with no real alternative evaluation needed at this scale. Confirmed free-tier-viable indefinitely at this scale (ADR-0002, D-21): the Developer plan's 5,000 errors/month and single-user limit both fit a solo founder comfortably, with no time limit and no overage billing — it simply stops accepting new events for the rest of the month rather than surprising anyone with a bill.
- **PostHog** — product analytics. Unchanged from the original plan. Doubles as the instrument for the north-star return-rate metric (`docs/RISKS.md`, North star metric) via anonymous IDs, since there's no login to key off of before M5 (ADR-0001, D-07). Confirmed free-tier-viable well beyond MVP-stage traffic (ADR-0002, D-21): 1M analytics events and 5,000 session replays per month, with unlimited team members — not a near-term concern at any point in this roadmap.

## Deferred, with reinstatement triggers

The reasoning behind each of these is in ADR-0001 in full (particularly D-04, D-10, D-12) and, for the first row, in ADR-0002 (D-20, D-24); this table states the resulting condition, not the argument for it (`docs/MVP_SCOPE.md`).

| Deferred | What it is | Trigger to reinstate |
|---|---|---|
| Claude API (Haiku 4.5 / Sonnet 5 / Opus 4.8, automated) | Scheduled API calls replacing the founder-run Claude Pro/Code sessions described above, for extraction fallback, topic synthesis, and thesis generation | Real revenue exists, founder-run sessions consistently exceed ~3–4 hours/week, content volume outgrows what one session can responsibly cover, or the founder decides the ~$13–25/month is worth paying regardless (ADR-0002, D-24) |
| FastAPI (deployed service) | A dedicated backend API layer | A consumer appears that isn't our own frontend, or logic emerges that can't live in a scheduled job or a Supabase RPC (ADR-0001, D-04) |
| Railway | Hosting for the above | Only relevant if FastAPI is reinstated — there's nothing else in this stack Railway would host |
| Celery + Redis | Task retries, controlled concurrency | Retries or concurrency are genuinely required — not anticipated at MVP job volume |
| Upstash | Managed Redis for the above | Only relevant once Celery is reinstated |
| `pgvector` | Embedding-based topic matching | Prompt-level topic continuity (`docs/AI_SYSTEM.md`) demonstrably fails to prevent topic fragmentation (ADR-0001, D-12) |
| Vector DB, external (Pinecone, Weaviate) | A dedicated vector database | Not anticipated at this scale under any current plan; `pgvector` inside the existing Postgres instance is the first, and likely only, escalation step |
| Reddit Data API | Content ingestion from Reddit | M0's human-read comparison shows meaningful earliness over RSS, *and* revenue exists to fund the commercial tier — the free tier is non-commercial-use only (ADR-0001, D-10). **Updated 2026-07-31:** the access model itself changed since this trigger was written — self-service app registration (reddit.com/prefs/apps) was replaced by a manual-approval ticket process (the Responsible Builder Policy, introduced late 2025), with multi-week waits and frequent non-response or generic rejection even for research-scoped requests. The policy also explicitly prohibits using Reddit data to train ML/AI models without separate approval — directly relevant if this connector is ever built to feed the Claude-based synthesis pipeline rather than for human-read research only; that specific use would need its own disclosure to Reddit, not an extension of whatever narrower approval covers today's research use. **Confirmed 2026-08-05:** Topicron's own request was rejected — a generic non-compliance response with no specific deficiency named. The predicted risk above materialized on the first attempt; not being reappealed without a concrete new basis to act on. |
| Massive.com (formerly Polygon.io) | Real-time market data | Revenue exists to justify the upgrade over free-tier Finnhub |
| Twelve Data (or a similar free-tier alternative) | Market data specifically for companies listed on non-US exchanges (XETRA, LSE, Euronext, Borsa Italiana, etc.) | Non-US-listed narratives become a recurring share of M0/M2 topics, not a one-off, *and* the candidate's free-tier coverage for the specific exchanges needed is verified directly with a real API call — the same discipline that confirmed the Finnhub gap above, not a repeat of trusting a vendor's marketing claim untested. Not yet evaluated this way; this row documents a candidate worth testing then, not a decision made now (M0 concierge-test finding, `m0/intervention-log.md`, rather than an ADR-0001/0002 decision like the rows above it) |

Auth doesn't appear in this table on purpose — Supabase, the tool, is already selected and provisioned above. What's deferred is turning it on, which is a product decision about user-specific state existing (`docs/MVP_SCOPE.md`), not a tool-selection question.

## What's avoided, not deferred

A few choices aren't on the table above because they're not trigger-gated at all — they're boundaries this stack doesn't cross regardless of pressure:

- **Scraping Reddit, or any source, as a workaround for API limits.** Reddit's terms explicitly prohibit it and the company actively defends against it (`docs/MVP_SCOPE.md`, Explicitly out of scope). The Reddit connector is deferred; scraping around the deferral is not an option that becomes available under any trigger.
- **Building against IEX Cloud.** Fully shut down in August 2024 — not a trade-off to weigh, just dead.
- **A second deployed service "just in case."** Every tool above earns its place by solving a problem that exists today. Standing up infrastructure ahead of a proven need is the overengineering this stack was rebuilt to avoid (ADR-0001, D-04).
- **Paying for automation before its own trigger fires.** ADR-0002 sets explicit conditions for reinstating the metered Claude API pipeline (D-24); reaching for a credit card the first time a founder-run session feels tedious isn't one of them. The trigger is time-on-task, capacity, or revenue — not a bad week.
